# Block Styling — Slice 0: Render the Settings Sidebar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render a `BlockInspector` settings sidebar in the Block Invoice Template editor so the already-built `InspectorControls` (Appearance panel, all `woi/column`/`woi/table` per-cell controls, heading level) become visible.

**Architecture:** The custom editor shell (`src/block-editor/index.js`) currently renders `BlockEditorProvider → BlockTools → Inserter → Canvas → Popover.Slot` with **no `BlockInspector`**, so every `InspectorControls` fill has no host slot and is silently dropped. This slice wraps the canvas and a new `<BlockInspector />` sidebar in a flex workspace row inside the existing `SlotFillProvider`/`BlockEditorProvider`, and adds structural CSS for the sidebar to the layout stylesheet.

**Tech Stack:** `@wordpress/block-editor` (`BlockInspector`), `@wordpress/components` (existing `SlotFillProvider`/`Popover.Slot`), webpack via `@wordpress/scripts`, the project's debug-Chrome live-testing harness.

### Task 1: Render the BlockInspector settings sidebar

**Files:**
- Modify: `src/block-editor/index.js` (the `Editor` component's returned JSX, ~lines 92–212)
- Modify: `src/block-editor/layout.js` (`LAYOUT_CSS` string, ~lines 7–20)
- Build artifact (committed): `assets/js/block-editor/*` (regenerated by `npm run build`)
- Version: `woocommerce-orders-invoice-pdf.php` (two lines, see Global Constraints)

**Interfaces:**
- Consumes: `BlockInspector` from `@wordpress/block-editor` (renders the selected block's `InspectorControls` fills; renders an empty state when no block is selected). Must sit inside the existing `SlotFillProvider` + `BlockEditorProvider` (it does).
- Produces: a visible settings sidebar. No new exported JS symbols; later slices rely only on the sidebar existing.

- [ ] **Step 1: Add `BlockInspector` to the block-editor import**

In `src/block-editor/index.js`, add `BlockInspector` to the existing `@wordpress/block-editor` import (lines 2–6):

```js
import {
	BlockTools,
	BlockEditorProvider,
	Inserter,
	BlockInspector,
} from '@wordpress/block-editor';
```

- [ ] **Step 2: Wrap the canvas + a new sidebar in a workspace row**

In `src/block-editor/index.js`, replace the canvas block inside `BlockEditorProvider` (currently lines 185–202, the `<div className="woi-block-canvas">…</div>` plus `<Popover.Slot />`) with a flex workspace holding the canvas and the inspector sidebar:

```jsx
<div className="woi-block-workspace">
	<div className="woi-block-canvas">
		<BlockTools>
			<div style={ { padding: '8px' } }>
				<Inserter rootClientId={ undefined } isAppender />
			</div>
			<Canvas
				previewCss={
					( window.woiBlocks &&
						window.woiBlocks.previewCss ) ||
					''
				}
			/>
		</BlockTools>
	</div>
	<div className="woi-block-sidebar">
		<BlockInspector />
	</div>
</div>
<Popover.Slot />
```

Leave the surrounding `<SlotFillProvider>` and `<BlockEditorProvider value={ blocks } onInput onChange>` exactly as they are — the workspace must stay inside both so the inspector's slot-fill and popovers resolve.

- [ ] **Step 3: Add structural CSS for the workspace + sidebar**

In `src/block-editor/layout.js`, append these rules to the `LAYOUT_CSS` string (after the base shell rules, before/with the `[data-layout]` rules). Keep the string-concatenation style already used in the file:

```js
'.woi-block-workspace{display:flex;gap:8px;align-items:stretch;min-height:0;min-width:0}' +
'.woi-block-canvas{flex:1;min-width:0;display:flex;flex-direction:column}' +
'.woi-block-sidebar{flex:0 0 280px;overflow:auto;min-height:0;background:#fff;border-left:1px solid #ddd}' +
'.woi-block-shell[data-layout="stack"] .woi-block-sidebar{flex-basis:260px}' +
```

(The `.woi-block-canvas` already exists as a bare class; this is the first rule for it. Adding `display:flex;flex-direction:column` lets the inner `.woi-canvas-scroll` — which is `flex:1` — fill the canvas column beside the fixed-width sidebar.)
